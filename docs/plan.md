## 1. 배경

컨테이너 이미지가 있는 곳이 지금 **포털 설정 하나**(`settings.app_image_dir =
/home/portal/images`)다. 이건 "모든 클러스터가 같은 경로를 쓴다"는 가정을 코드에 박아
둔 것이고, 그 가정이 성립하는 이유는 dev01·slurm01·slurm02가 **같은 NFS export**
(`198.19.64.8:/scp_users_tl8g1s`)를 마운트하고 있어서다.

**향후 클러스터마다 다른 NFS를 쓴다**(사용자 확인). 그러면 이 가정이 깨진다.

마이그레이션 `0017`이 위치를 클러스터에서 포털로 옮긴 근거는 두 개였는데, 그중
"이미지를 바꾸려면 클러스터를 고쳐야 하는데 정작 바뀌는 것은 앱"은 **파일명**에 대해
맞는 지적이었고 그대로 유지한다. 나머지 "두 클러스터가 같은 경로를 쓰고 있었고"는
**그때 마침 그랬다는 사실**이지 구조가 아니었다. 위치만 되돌린다.

두 번째 문제는 `ready`다. 앱이 열려 있는지를 **코드 상수**가 정한다. SIF를 만들어
올려도 `batch_apps.py`를 고쳐 재배포해야 앱이 열린다 — 파일이 있는지는 파일이 안다.

## 2. 설계 — 위치를 `home_base`에서 파생한다

새 컬럼을 만들지 않는다. **클러스터별 파일시스템 경로는 이미 있다** — `cluster.home_base`
(SCR-18 "홈 상위 경로"). 여기서 파생하면 per-cluster 변화가 공짜로 나오고, 별도 칸이
없으니 **공유되지 않는 로컬 경로가 들어갈 여지도 없다**(`home_base`는 파일 관리자가
매일 검증하는 값이다).

```
home_base 있음   →  {home_base}/.portal/images
home_base 비었음 →  settings.app_image_dir      (폴백, 기본 /home/.portal/images)
```

폴백이 필요한 이유는 `home_base`가 선택 입력이라서다(비우면 `getent passwd`로 사용자별
자동 인식 — 그때는 "상위 경로"라는 개념 자체가 없다).

### 왜 `portal`이 아니라 `.portal`인가

`{home_base}` 아래는 **사용자명이 오는 자리**다. `portal`은 유효한 사용자명이라, AD에
그 이름의 계정이 생기면 홈 프로비저닝이 이미지 저장소 위로 떨어진다. 앞에 점이 붙으면
POSIX/AD 사용자명이 될 수 없어 충돌이 구조적으로 불가능해진다.

같은 파일시스템 안 `mv`라 8.9GB는 움직이지 않는다. 아이콘(`app_icon_dir`)도 같은 자리에
있어 함께 옮긴다 — 같은 이유로 같은 위험을 지고 있다.

### 포털은 디렉터리를 만들지 않는다

`{home_base}`는 root 소유이고, 여기에 만들려면 권한 상승이 필요하다. 포털이 지금
**사용자 본인 홈 밖으로는 쓰지 않는다**는 경계(CLAUDE.md "허용 루트는 홈뿐이다")를
깨는 첫 사례가 된다. 얻는 건 `mkdir` 한 번이고 — 이미지는 여전히 손으로 넣어야 한다.

대신 **클러스터 등록 시 확인해서 말한다.** 등록은 이미 `등록 → 자격증명 저장 →
REST 연결 확인`을 이어서 돈다. 여기에 디렉터리 확인을 더한다. 없으면 경고를 띄우되
**등록 자체는 막지 않는다** — 순서를 강요하면 클러스터를 먼저 등록할 수 없다.

### 존재 판정이 `ready`를 대체한다

목록 응답에 `installed`를 더하고 잠금을 셋으로 나눈다:

| 필드 | 의미 | 출처 |
|---|---|---|
| `ready` | **실행 방식**(커맨드·파라미터)이 확정됐나 | 코드 카탈로그 |
| `installed` | 이 클러스터에 이미지 파일이 있나 | 클러스터 `ls` (신규) |
| `allowed` | 이 사용자가 쓸 자격이 있나 | `app_access` (기존) |

`ready`는 없애지 않고 **의미를 좁힌다.** Isaac Sim이 좋은 예다 — 지금 `ready=False`인
이유가 두 개인데(이미지 없음 + 커맨드가 실측이 아님), 뒤의 것은 남는다. 이미지가
생겨도 `ready=False`가 맞다.

### 목록 조회가 파드를 떠난다

`GET /ops/app-images`는 **백엔드 파드의 파일시스템**을 읽는다. 이게 동작하는 유일한
이유가 dev01이 클러스터와 같은 NFS를 마운트하고 있어서다. 클러스터별 경로가 되면 성립하지
않는다 — 파드 마운트는 Deployment에 정적으로 박혀 있어 클러스터를 등록해도 생기지 않는다.

`GET /clusters/{cid}/app-images`로 옮기고 **로그인 노드 SSH `ls`**로 읽는다. 파일 관리자가
이미 쓰는 경로라 새 인프라가 아니다. 부수 효과로 **파드의 `app-images` hostPath 마운트가
불필요해진다**(Deployment에서 제거).

## 3. 사용자 결정 사항

| 항목 | 결정 |
|---|---|
| 계산 노드 → 레지스트리 연결 | **포털 구성의 전제조건**으로 한다 (현재 충족) |
| 이미지 디렉터리 권한 | 필요한 쓰기 권한으로 조정 가능 |
| 클러스터별 NFS | 개발 구성은 공유, **향후 분리** |
| 디렉터리 이름 | `.portal` |
| 생성 주체 | 포털은 만들지 않고 **등록 시 확인만** |
| `ready` | **파일 존재로 자동 판정**(`installed` 신설) |
| 범위 | 계획 세우고 **순차 진행** — 전체 |

## 4. 범위

**포함 (5단계)**
1. 경로 파생 + `.portal` 이동
2. 클러스터별 이미지 목록(SSH) + 등록 시 디렉터리 확인
3. `installed` 판정 → 잠금 셋
4. `app_catalog.image_ref` — 이미지의 출처(OCI 참조)를 DB에 남긴다
5. 변환을 Slurm 잡으로 — `apptainer build docker://…`

**제외**
- Helm 차트의 마운트 누락 정정 — 이 에픽과 무관한 기존 드리프트다(별건으로 보고만)
- 레지스트리 자격증명 관리 — 현재 대상 이미지가 전부 공개다. 필요해지면 기존
  Secret 저장소(`PORTAL_SECRET_*`)에 붙인다
- 이미지 삭제·가비지 수집 — 실행 중 세션이 SIF를 mmap하고 있어 별도 검토가 필요하다

## 5. 위험

| 위험 | 대응 |
|---|---|
| 변환 실패로 **잘린 `.sif`**가 남아 `installed`가 참이 된다 | `.tmp`로 쓰고 완료 후 `mv`(같은 FS라 원자적) |
| apptainer 캐시가 쌓여 DiskPressure — **전례 있음**(11GB, 파드 evict) | 잡 스크립트에서 `APPTAINER_CACHEDIR`·`TMPDIR`을 둘 다 홈 아래로 |
| 변환 잡이 관리자 계정으로 도는데 디렉터리가 root 소유라 못 쓴다 | 운영 절차로 그룹 쓰기 권한 부여(§3 확인됨). 문서에 명시 |
| SSH `ls`가 목록 렌더마다 왕복 | Redis 60초 캐시(`_idle_ttl_seconds`와 같은 패턴) |
| 로그인 노드가 죽으면 앱 목록이 통째로 막힌다 | `ls` 실패는 **빈 목록**으로 흡수 — 앱은 잠기지만 화면은 뜬다 |

## 6. 수용 기준

- [ ] 클러스터마다 다른 `home_base`를 넣으면 이미지 경로가 클러스터별로 갈린다
- [ ] `home_base`가 비면 오늘과 **똑같이** 동작한다(설정 변경 0건)
- [ ] SIF를 디렉터리에 넣으면 **코드 배포 없이** 앱이 열린다
- [ ] 이미지가 없는 클러스터에서 앱이 **숨지 않고 잠기며 이유를 말한다**
- [ ] 디렉터리가 없는 클러스터를 등록하면 경고가 뜨고 **등록은 된다**
- [ ] 백엔드 pytest 전부 통과, 프론트 빌드 통과
