# Plan: admin 화면 — 등록/수정 입력을 모달로 전환

- 작성일: 2026-07-21
- 관련 화면: SCR-11(nodes), SCR-13(users), SCR-14(reports), SCR-15(settings), SCR-17(license), clusters/billing/jobs
- 상태: Draft (승인 대기)

## 1. 목표 / 배경
admin 콘솔 전 페이지가 **엔티티 등록/수정 입력을 상시 인라인 카드**로 두거나, **"추가/등록/생성" 버튼만 있고 입력 폼이 없는(dead-end)** 안티패턴을 반복한다. 등록/수정은 목록에서 버튼을 눌러 **모달 다이얼로그**로 입력받는 것이 맞다(사용자 지적: license.html의 "수집/연동 설정").

## 2. 설계 / 접근
- **기존 모달 패턴 재사용** (신규 컴포넌트 금지): `<div class="modal-backdrop hidden" id="xModal"><div class="modal" role="dialog">` + `.modal-head/.modal-body/.modal-foot`, JS로 `hidden` 토글, `.m-close`/배경클릭/ESC 닫기. user 페이지(files/notices)와 동일 컨벤션.
- 입력 컨트롤도 기존 클래스 재사용: `.input`, `.select`, `.switch`.
- 각 페이지에 작은 open/close JS를 기존 스크립트 블록 컨벤션대로 추가. 트리거: 페이지 액션 `＋등록` = 빈 폼, 행 `수정` = 값 프리필(정적이므로 예시값).
- **fid 칩/주석은 모달 안으로 그대로 이동**해 추적성 유지.
- 사이드바/톱바 미변경(본문 content만 수정 → 18파일 복붙 규칙 비해당).

## 3. 케이스 분류 (조사 결과)

### Tier 1 — 인라인 폼이 이미 존재 → 모달로 이전 (사용자 예시와 정확히 일치, 저위험)
| 파일 | 인라인 블록 | 트리거 |
|---|---|---|
| license.html | 수집/연동 설정 (L128–163) | ＋라이선스 서버 추가 / 행 수정 |
| clusters.html | 클러스터 등록/수정 (L136–161) | ＋클러스터 등록 / 행 수정 |
| nodes.html | 노드 상태 변경 (L153–164) | 행 Drain/Resume/상세 |
| jobs.html | 우선순위 조정 (L159–172) | 행 ⇧Top/Hold |
| users.html | QOS 생성/수정 + 파티션 접근제어 서브폼 (L246–272) | ＋QOS 생성 / 행 수정 |

### Tier 2 — 버튼만 있고 폼 없음(dead-end) → 신규 모달 폼 생성
| 파일 | 대상 | 
|---|---|
| nodes.html | 파티션 생성/수정, 예약 생성 |
| settings.html | 공지 등록/수정, 앱·템플릿 등록/파라미터 |
| billing.html | 자원 식별 필터 규칙 추가/수정 |
| reports.html | 정기 리포트 설정 |

### 유지(인라인이 타당) — 변경 안 함
- dashboard.html 전체(대시보드), 각 페이지 검색/필터 바, 읽기전용 테이블·차트·타임라인
- settings.html 시스템 설정(L143–171, 전역 포털 설정), users 계정·클러스터 매핑 매트릭스
- **경계 케이스**(별도 결정): users AD 연결(L148–191), billing SCP 연동(L162–201) — 단일 인스턴스 통합 설정이라 인라인도 방어 가능하나 "설정" 버튼이 모달을 암시

## 4. 제약 / 리스크
- 정적 프로토타입 + 바닐라 JS. 프레임워크 도입 없음(정적 원칙 유지).
- 회귀 위험: 모달 오픈/클로즈 JS, 태그 균형, 내부 링크. → portal-verifier로 검증.
- 고위험(보안/권한/DB) 아님. UI 구조 변경 수준.
